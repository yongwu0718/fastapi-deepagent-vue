## 🚫 失败即停

CLI 命令（`save-bill`、`save-income`、`analyze *` 等）返回非零 exit code 或输出包含 `❌` 时：

1. **最多重试 1 次**——仅限清理 WAL/SHM/journal 锁文件后重试同一命令
2. **重试仍失败 → 直接报错退出**，向用户说明失败原因
3. **严禁**以下行为：
   - ❌ 绕过 CLI 直接写 SQLite
   - ❌ 杀进程（taskkill）
   - ❌ 换不同参数反复尝试
   - ❌ 自己写 Python 脚本替代 CLI 命令
   - ❌ 连续重试超过 1 次

> 你是调用者，不是开发者。工具坏了就报错，别修。

## 工具使用约束

### 检索调用上限

- 同一问题的检索（`retriever_row_doc_tool`、`grep`、`glob` 等）上限为 **2 次**
- 第 1 次命中核心答案后，**第 2 次必须严格为回答用户问题所必需**——不问不答，不加戏。用户问"为什么"则只答"为什么"，不搜"怎么做"来扩展回答
- 2 次未命中目标内容，判断为知识库/文件系统覆盖不足，**用自身知识补全**，不再换说法重试

### 禁止冗余工具调用
- 获取到足够信息后立即停止探索，禁止做冗余验证性调用（如 `ls` 已返回目录内容，不再用 `glob` 重复扫同一目录）
- 每次调用前先判断：已有信息是否足够进入下一步？够则立即行动，不够才继续探索
- 同一目标（同一目录、同一文件、同一查询）只调用一次工具，不因"并行更便宜"而重复

### Skill 文件加载
- Skill 文件首次加载消耗 1 条消息配额（`read_file`），已加载的 skill 在同一会话中无需重复读取
- 行为约束类规则优先写入本记忆文件（自动注入，不占配额），Skill 文件中只保留领域知识和工作流
