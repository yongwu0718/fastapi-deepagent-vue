# Frontend Overview

## Stack and conventions

Vue 3 (Composition API + `<script setup>`), TypeScript strict, Vite 8, Vue Router 4 (hash history), no third-party UI kit — all components are hand-written. Markdown rendering is `marked` + `markdown-it` plugins (katex, multimd-table) sanitized with DOMPurify; `mermaid` is a dependency and used in chat rendering. `split-pane-v3` powers resizable panels. The generated API client is `@hey-api/openapi-ts` output.

## Entry and routing — `src/main.ts`, `src/router/index.ts`

- `main.ts` installs global `errorHandler`/`warnHandler` that log through the shared Vue logger (`src/shared/useLogger.ts`).
- Router (hash mode):
  - `/` → redirect to the last active thread (`chat_active_thread_id` in localStorage) or a new `crypto.randomUUID()` thread.
  - `/chat/:threadId` → `layout/ChatLayout.vue` (the main workspace).
  - `/settings` → `settings/SettingsView.vue`.
  - `/rag` → `rag/RagManagement.vue`.

## Layout system — `src/layout/`

`ChatLayout.vue` composes the chat area, the resizable right sidebar (`sidebar/RightSidebar.vue` with Details/Outline/Tools tabs) and the threads sidebar (`threads/ChatSidebar.vue`); `useFilePanelResize.ts` manages panel drag persistence. `threads/useChatHistory.ts` caches per-thread messages and branch leaf ids in localStorage for refresh recovery.

## API client — `src/api/`

- `chat.ts` — hand-written types + helpers: `Message` (with `_checkpointId`, `_parentCheckpointId`, `_leafCheckpointId`, `_msgId` binding fields), `StreamChunk`, HITL types (`ActionRequest`, `ReviewConfig`, `HITLDecision`), multimodal content helpers (`getContentText`, `getContentBlocks`, `normalizeContent`, `mergeConsecutiveReasoningMessages`).
  - `mergeConsecutiveReasoningMessages(msgs, skipToolMessages = false)` merges **consecutive reasoning-only assistant messages** (empty `content`, no `contentBlocks`, but `reasonContent` set) into one assistant message whose `reasonContent` is joined with `\n\n---\n\n`, so the history list does not show a run of empty assistant rows. `skipToolMessages = true` (used by the **render layer**, `ChatMessages.vue` line ~50) treats `tool` messages as transparent — they do not break the reasoning chain but stay in the result array (hidden by `v-if` in the template); the **data layer** (default `false`, used by `useChatController` when loading server history / switching branches and by `threads/useChatHistory.ts` for the cached refresh history) flushes the pending reasoning merge when it hits a tool message.
- `client/` — generated by `npx @hey-api/openapi-ts -i http://localhost:8000/openapi.json -o src/api/client` (command documented in `server-ops.md` and `notes/api.md`): `client.gen.ts`, `sdk.gen.ts`, `types.gen.ts`, `index.ts`. Regenerate after backend schema changes; the generation log `frontend/openapi-ts-error-*.log` shows a past failed run.
- `files.ts` — hand-written file-browser API calls.
